evidence: The #390 plane transport's cost is the sublattice it builds (#390)

The Otilde(T_Co) plane row's per-plane transport was measured last turn as
88 % of the row at 637 ms a plane, rising as the row advances, with its
interior unsplit.  This splits it: three runs of the public
`isotropic_orbit_representatives(2)` on `T_Co` under `Otilde`, on main
a71272add9, with the same probe.  No library code is changed.

The four steps of the subobject branch, mean ms per call, first window
against the last of the 2700 s run (4672 of 189720 planes, 2158.3 s of
transport = 79.9 % of the row at 462 ms a plane):

  product      0.22 ->    0.23   x1.04     the composed morphism
  image       19.65 ->  435.91   x22.2     (self * obj.inclusion()).image()
  basis        1.22 ->    1.44   x1.18     the generators read off the image
  admission   22.83 ->  228.25   x10.0     primitive_isotropic_subobject
  ---- inside the admission, one call each per plane
  subobject_on 8.88 ->  217.41   x24.5
  is_primitive10.31 ->    6.97   x0.68
  refine       0.39 ->    0.36   x0.92

The two steps that build a subobject parent hold the whole rise; the two
that do algebra on the plane's own vectors are flat.  The framing is 0.02 ms,
so the four steps are the call.

Two shorter runs place it further, in windows of 50 planes:

* `detail=image`, 1000 s, 2868 planes: `image` 9.31 -> 239.41 ms and the
  `subobject_on` call inside it 8.86 -> 239.31 ms, so the image step is its
  own span construction to 0.1 ms; the admission's `subobject_on` is the
  same growth one call later, 3.41 -> 119.05 ms.
* `detail=span`, 700 s, 2005 planes: inside `subobject_on`,
  `_span_basis_elements` is flat, 2.45 -> 2.68 ms per call (x1.09), and
  `_lattice_subobject_spanning` is 3.93 -> 126.82 ms per call (x32.3),
  twice per plane (admission.subobject_on 3.46 -> 85.09, image
  9.33 -> 174.01, the call 22.25 -> 269.07).

So the new algorithm belongs to the sublattice construction
(`_lattice_subobject_spanning` / `_lattice_object` with its
`ModuleSubobjectConstruction`), not to the isometry application, not to the
span-basis linear algebra, and not to the walk.  The cost is very nearly
linear in the number of planes already built: 0.037 ms per previous plane
per span-construction call over 0-2005 planes.

What it is not, from the same windows:

* not the cyclic collector: 6615 collections for 20.0 s over the whole
  2700 s, at most 2.8 % of any window's transport (from gc.callbacks);
* not a UniqueRepresentation table: the class-level table the reached
  classes construct through, OwnedJoinCategory_with_category, sits at
  1746 -> 1718 entries, flat;
* not a cache lookup: the one table that grows is the admission's own
  `_cache__primitive_isotropic_subobject`, 267 -> 4689 entries, one per
  plane, a dict;
* the heap does grow: 2.98 M -> 8.42 M live objects (+1160 per plane:
  list, tuple, dict, the element class, and MonoDict with its eraser at
  ~80 per plane), RSS 1425 -> 2158 MiB at 0.165 MiB per plane.  Which of
  those a construction call scans is the next measurement; the MonoDict
  count is the only one that grows per plane in the same proportion, and
  it is named here as the candidate, not as a finding.

At the run's own mean 189720 planes are 24.3 h, and the mean rises with the
planes already built, so that is a lower bound; at 0.165 MiB per plane the
retained planes are over 30 GiB.  The row does not fit this VM, whatever the
algorithm.

The probe is in-process instrumentation only.  It replaces the branch by the
library's own four expressions under a clock each and checks the result
against the unmodified branch on the first three calls (generator
coordinates equal; 0 divergences); it times the interior from wrappers that
resolve each `CachedMethod` through its descriptor and drop the instance
shortcut Sage stores, so the cache stays in force and every call is timed --
the previous probe's patch answered one call for exactly this reason.  The
admission wrapper's own cost is reported as the difference between the step
and the method it times: 0.01-0.04 ms per call.  Each window also snapshots
the live objects by type and the cache tables, whose own cost is printed
with them (0.8-1.9 s).

Logs and probe in .tmp/qc-evidence/, with rows in INDEX.md and digests in
SHA256SUMS: `issue390-transport-split.py`, `-split.log` (2700 s, cap hit),
`-image-detail.log` (1000 s), `-span-detail.log` (700 s), and the two smoke

"637 ms a plane" both measured a stage nobody had split; the per-plane cost
is a span construction whose cost grows with the row.
