# sage-extensions#32: the integer translation coequalizer is the orbit set of its action

Base: published `main` `e2803c36`.  Commits: `8ad4602` (test), the `fix:` commit
on top of it.  Files: `categories/sets/set_categories.py`,
`categories/rings/ring_foundation.py`, `categories/group/g_sets.py`,
`tests/sets/test_equalizers_and_coequalizers_of_finite_sets.sage`.

## The defect

On `e2803c36` the general set coequalizer decided the integer-translation case
inside `Sets`:

* `_categorical_coequalizer_construction` (ll. 1894–1910) tested
  `source is target and target is _own_ring(SageZZ)`, then
  `isinstance(..., OwnedSetMorphism)` and read
  `selected_integer_translation_step()`;
* `_categorical_coequalizer_family_construction` (ll. 2026–2041) repeated the
  same identity and class tests.

`AGENTS.md`, *What optimization is for*, requires the algorithm to live in the
structure's own category with placement choosing it, and *Dynamic peeking is
prohibited* bans `isinstance` in mathematical preamble code.  The branch was
also incomplete: two separately constructed translations by `2` are equal
arrows whose coequalizer is `id_ZZ`, and the pair `(t_2, t_3)` generates the
congruence modulo `1`, whose quotient is a point.  Both fell through to
`_GeneratedRelationQuotient`, which answers `generated_equivalence(...)` — an
undecided proposition — for class equality and cardinality.

## The repair

The quotient is now asked of the set itself through the optional operation
`Sets.ParentMethods.generated_relation_quotient(morphisms)` (declared on the set
owner, `NotImplemented` by default).  The owned ring answers it for its selected
additive translations `t_r: x |-> x + r`, the identity being `t_0`:

* displacements `r_1,...,r_k` give the relation `x ~ x + (r_i - r_j)`, so its
  classes are the cosets of the ideal of the pairwise differences;
* the cyclic group generated by `step = gcd(r_i - r_j)` acts on the ring by
  `k . x = x + k*step` (`Groups.Free(1)` presented as the infinite cyclic
  group); `g_sets._translation_orbit_set` returns that action's **orbit set**
  (`_OrbitSet`, specialized as `_TranslationOrbitSet`), its projection from the
  ring, and one point per class;
* the ring's maintained ideal quotient decides the class relation and, when
  finite, gives the number of classes;
* `step = 0` is the identity quotient; any non-translation family answers
  `NotImplemented` and keeps the general represented construction.

The old `_integer_translation_relation_quotient` helper is deleted.  No
`isinstance`, object-identity test, `_own_ring` test or
`selected_integer_translation_step` call remains in either coequalizer method;
`selected_integer_translation_step` is now read only by the ring owner, on its
own arrows.

## Mathematics

For a parallel family `t_{r_1},...,t_{r_k}` the generated relation is
`t_{r_i}(x) ~ t_{r_j}(x)`, i.e. `x ~ x + (r_i - r_j)`.  Both inclusions:

* every generating step changes a point by a difference `r_i - r_j`, hence
  preserves congruence modulo `g = gcd(r_i - r_j)`;
* every multiple of `g` is an integral combination of the differences
  (Bezout), and each summand is traversed by one forward or reverse generating
  step, so every pair congruent modulo `g` is connected by finitely many steps.

So the classes are the cosets of `gZZ`.  The universal property: a map
`h: ZZ -> X` coequalizes the family exactly when `h(x) = h(x + r_i - r_j)` for
all `i,j,x`, i.e. when it is constant on cosets; it then factors uniquely
through the projection.  `g = 0` is the trivial subgroup and the identity
quotient.  `d = 2` with the identity in the family is the parity case.
