# issue 297: the cusp-anchored chamber, for a reflection subgroup given by its reflections

The operation is `HyperbolicLattices(ZZ)(K).subgroup_fundamental_chamber(generators=…)`,
and the mechanism under it `fundamental_chamber(admits_root=…)`: Vinberg's
algorithm with a root filter, which is the finite-index subgroup version of
`fundamental_chamber()`.  The acceptance — the five wall counts of Sterk's cusps
read from the `gamma-en-2` card by tag — is blocked on
`dzackgarza/lattice-database#33`, which has not landed; what is measured here is
recorded instead.

## 1. Why the filter has to sit inside the algorithm

`vinal`'s `VinAl` enumerates the roots of the whole lattice and accepts a
candidate when it is a root of that lattice and lies beyond the walls already
found (`IsRoot`, `IsNewRoot`, `FindRoots`).  A reflection subgroup
`W' = ⟨s_r : r ∈ S⟩` of finite index has its own polyhedron, the intersection of
the half-spaces of `W'`'s root system, so a candidate must *also* have its
reflection in `W'`.  Filtering the full group's wall list afterwards would return
a smaller cone that is not a fundamental domain of anything.

So the restriction is a subclass of `VinAl` that adds one test to `IsRoot`
(`_vinal_vinberg_roots`, `admits_root`), which both the candidate enumeration and
`FundCone` — the roots of the initial cone at the controlling vector — go through:

```python
class _FilteredVinAl(VinAl):
    def IsRoot(self, vector):
        return super().IsRoot(vector) and bool(self._admits_root(tuple(int(e) for e in vector)))
```

`_vinberg_search` takes the filter in **lattice elements**, not engine rows, and
applies the sign convention of `_engine_gram_of_signature_n_1` before asking; the
public keywords are `fundamental_chamber(admits_root=…)` and
`vinberg_simple_roots(admits_root=…)`.

`subgroup_fundamental_chamber(generators=…)` builds the filter from a subgroup
given by isometries: a root is admitted when `lattice.reflection(root) in
subgroup`, the subgroup's own membership test, memoised per call because the
algorithm asks about the same root once per decomposition.  An undecided
membership propagates from the group machinery rather than being guessed.

## 2. What is measured

On Sterk's cusp lattice `U + E8(-2)` (`NamedLattices.U_E8_2`), rank 10,
signature (1,9), determinant -256 (`issue297-probe.log`):

```
cusp lattice: rank 10, signature (1, 9), det -256
full chamber: 10 walls in 4.3s, complete True
    root squares: [-4, -4, -4, -4, -4, -4, -4, -4, -2, -4]
```

Ten walls, the search completing — the fixed point the restricted operation must
reproduce when nothing is refused.  Sterk's five cusp diagrams
(`Sterk.sterk_roots()`, §4.3.5–4.3.9) have 12, 10, 12, 11 and 14 walls, so four of
the five are chambers of *proper* reflection subgroups and the unrestricted
chamber reproduces only one of them — which is exactly why #285 could not be
satisfied by `fundamental_chamber()`.

Two costs are measured and both are stated in the code:

- the filter is called once per candidate root per decomposition, so the
  generic `generators=` path is only as fast as the subgroup's membership test;
  with the reflection subgroup generated by nine of the ten walls of
  `U + E8(-2)` that test did not return within six minutes and the run was
  stopped — and tightening the algorithm's own bounds to 20 decompositions did
  not help, so the cost is the membership decision and not the enumeration.  The
  path #285 needs is the other one — `admits_root=` with a *decidable*
  criterion, which for `G_v` is the discriminant test of #312, and that is one
  computation in the finite group `O(A_L)` per root;
- the full chamber of this lattice costs 4.3 s, so the algorithm itself is not
  the bottleneck.

## 3. What is blocked, and on what

The expected wall counts come from the `gamma-en-2` row of card `029J`, and that
row states `lines` and `planes` only: the digest at pin
`d6a539339bac5ea0ee8d8bde5dc19564955eb152` has no wall count, and no per-cusp
diagram data for it anywhere (`cusp` appears seven times, all in citations).
`dzackgarza/lattice-database#33` must land and the digest be regenerated by
`tests/cards/refresh_lattice_database_enriques.py` before the five counts can be
read by tag.  Until then the test asserts what the operation measures (the full
group's ten, and that a refused root is not a wall while every returned wall
passes the filter) and names the card in its docstring.

## 4. The tests

`tests/lattices/test_the_subgroup_cusp_chamber.sage` — two tests, both through
the public operation: the full chamber's ten walls with every root of square -2
or -4 and the search completing, and a refused root absent from the restricted
chamber while every returned wall passes the filter.  `2 passed in 27.67s`
(`issue297-test5.log`).  `subgroup_fundamental_chamber(generators=…)` is not
asserted in the suite: on every bound tried its membership test was the slow
step measured above, and a test that hangs is not evidence about the filter.
