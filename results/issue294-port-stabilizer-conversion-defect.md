# Exact engine defect: the line-stabilizer family is converted to full integral isometries before returning

For `dzackgarza/sage-indefinite-port` at held `991b88b0`. Reproduced from the consumer
side on the Enriques case-1 public call; this repository is not changed.

## The consumer path, with the observed stack

`Involution.polarized(h).coinvariant_extension_subgroup()` (the DSH eq. (5) preimage,
built in 121.7 s) is asked for its isotropic line orbits.  The call runs

```
probe → predicate_subgroups.py:526 isotropic_orbit_representatives
      → orthogonal_quotients.py:1791 _subgroup_isotropic_orbit_representatives
      → lattice_morphisms.py:4182 isotropic_stabilizer_generators
      → isotropic_orbits.py:993 _isotropic_stabilizer_generators
      → marked_lattices.py:116 automorphism_group_generators
      → isotropic_induction.py:310 line_automorphism_generators
      → isotropic_induction.py:304 _stabilizer_generators  (genexpr)

      → lattice_morphisms.py:1482 integral_restriction
      → module_morphisms.py:1116 _call_        (rational evaluation per basis vector)
```

Two faulthandler dumps taken 600 s apart during the run both sit in this
`_stabilizer_generators` genexpr, so the run is inside the conversion of the family, not
inside the orbit enumeration or the double-coset computation.

## The defect

`isotropic_induction.py:304`:

```python
return tuple(lattice.integral_isometry(generator)
             for generator in action.stabilizer().group_generators())
```

Every element of the stabilizer family is raised to a **full owned integral isometry**,
and `integral_restriction`'s fast path builds the coordinate matrix *and its certified
inverse* (`coordinates.inverse()`) per element.  The consumer of this family in this
repository uses only the induced **discriminant action**: `OrthogonalCharacterQuotient`
reads `rho(s)` per generator and feeds the images to its double-coset computation.  The
full isometry with inverse is never used by that consumer.

For an integral isometry `s` of a lattice `L`, the induced discriminant automorphism is
the **forward class action** `[z] ↦ [s·z]` on `L*/L`: no inverse of `s` is needed,
because `s` preserves `L` and the form and therefore maps `L*` onto `L*`.  The owner in
this repository currently computes that same map through
`LatticeIsometryMethods.discriminant_isometry`, whose forward morphism inverts `s` only
because it works in dual coordinates — a convenience, not a necessity.

## What would remove the cost

Either exposure is sufficient, and neither changes the mathematical result, because the
induced action is the same map:

1. return the raw stabilizer family (the rational isometries
   `action.stabilizer().group_generators()`) and let the consumer induce the class
   action itself; or
2. return the family's images directly in `O(A_L)` as a subgroup
   `⟨rho(s_i)⟩ ≤ O(A_L)`.

The repository's consumer preserves exact image equality in either case: the subgroup it
uses is generated by `rho` of the same family, with no overgroup, no arbitrary lifts and
no cardinality proxy.

## Scale

`|A_N| = 1024` for `N = U + U(2) + E8(-2)`, so the class action per generator is a
1024-class permutation computable from the forward matrix alone, while the current route
pays a full isometry construction with inverse per element.  The family's size is
whatever `action.stabilizer().group_generators()` returns; it is not asserted here, since
this repository has not measured it on this specimen — the dumps place the run in the
loop and that is all that is claimed.
